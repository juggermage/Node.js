# Тест-кейси REST API — коло №1

**Проєкт:** система управління приватним дитячим садком (серверна частина)
**Автор:** Зубик Діана, Quality Assurance
**Коло:** №1 — базові CRUD-модулі, дані зберігаються у тимчасових масивах

## Загальна інформація

| Параметр | Значення |
|---|---|
| Базовий URL | `http://localhost:3000/api/v1` |
| Інструмент | Postman або Bruno |
| Запуск сервера | `npm run dev` |
| Формат тіла запитів | JSON (`Content-Type: application/json`) |

**Формат успішної відповіді:**
```json
{ "success": true, "data": {} }
```

**Формат відповіді з помилкою:**
```json
{ "success": false, "message": "Resource not found" }
```

**Статуси першого кола:** `200 OK`, `201 Created`, `204 No Content`, `400 Bad Request`, `404 Not Found`.

**Статуси тестування:**

| Статус | Значення |
|---|---|
| Not Run | тест ще не виконувався |
| Passed | тест пройдено |
| Failed | виявлено невідповідність очікуваному результату |
| Blocked | тест неможливо виконати через певну проблему |

Усі тестові дані вигадані, реальні персональні дані дітей і батьків не використовуються. Поки тест не виконано, його статус — `Not Run`, а фактичний результат не заповнюється.

## Модуль children (діти)

### TC-001 — Успішне створення дитини
- **Модуль:** children
- **Тип:** позитивний
- **Що перевіряється:** створення запису дитини з коректними даними та поява його в загальному списку
- **Передумови:**
  - сервер запущений;
  - маршрут `/api/v1/children` доступний
- **HTTP-запит:** `POST http://localhost:3000/api/v1/children`
- **Тестові дані:**
  ```json
  {
    "firstName": "Марія",
    "lastName": "Тестова",
    "birthDate": "2022-05-10"
  }
  ```
- **Кроки виконання:**
  1. Відкрити Postman або Bruno і створити POST-запит на вказаний URL.
  2. У Body вибрати JSON і вставити тестові дані.
  3. Натиснути Send.
  4. Перевірити статус і тіло відповіді.
  5. Надіслати `GET http://localhost:3000/api/v1/children` і перевірити, що новий запис є у списку.
- **Очікуваний результат:**
  - HTTP-статус `201 Created`;
  - у відповіді `success: true`;
  - створений запис має унікальний ID;
  - дані дитини відповідають надісланим;
  - запис присутній у загальному списку.
- **Фактичний результат:** —
- **Статус:** Not Run

### TC-014 — Відхилення часу завершення, що не пізніший за початок
- **Модуль:** schedules
- **Тип:** негативний
- **Що перевіряється:** заборона створення заняття, якщо час завершення раніший за початок або дорівнює йому
- **Передумови:**
  - сервер запущений;
  - маршрут `/api/v1/schedules` доступний
- **HTTP-запит:** `POST http://localhost:3000/api/v1/schedules`
- **Тестові дані:**

  Варіант А — завершення раніше за початок:
  ```json
  {
    "date": "2026-10-20",
    "startTime": "11:00",
    "endTime": "10:00"
  }
  ```
  Варіант Б — завершення дорівнює початку:
  ```json
  {
    "date": "2026-10-20",
    "startTime": "10:00",
    "endTime": "10:00"
  }
  ```
- **Кроки виконання:**
  1. Створити POST-запит на вказаний URL.
  2. Надіслати дані варіанта А, перевірити статус і тіло відповіді.
  3. Надіслати дані варіанта Б, перевірити статус і тіло відповіді.
- **Очікуваний результат:**
  - для обох варіантів HTTP-статус `400 Bad Request`;
